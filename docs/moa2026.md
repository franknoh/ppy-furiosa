# MOA 2026 Gemma 4 Stage 1 baseline audit

## Source identity and scope

The official baseline is `micro2026-moa/furiosa-opt-gemma4-12B`, commit
`850428729c1b9af0c0b86a9cf694e3b4b4486b29`. The inspected checkout at
`build/reference/furiosa-baseline` was clean. This audit reads the complete
`src/ops.rs`, `src/device/layout.rs`, `src/device/shared/{mlp,rmsnorm,residual}.rs`,
every file in `src/device/sliding/`, `src/axes.rs`, `src/lib.rs`, `Cargo.toml`,
`OPTIMIZATION.md`, `tests/test_kernels.rs`, and the local/Arena test scripts.
`scripts/rngd_test.sh` exists.

The crate is `furiosa-opt-gemma4` 0.1.0, Rust edition 2024, with
`furiosa-opt-std = "0.6.0"`. `rust-toolchain.toml` selects
`nightly-2026-05-01` with rustfmt and clippy. The README selects
`cargo-furiosa-opt@0.6.0` on x86_64 Ubuntu 22.04+ / GLIBC 2.34+.

Stage 1 preserves every device function's name, signature, return type, and
module path. Only `src/device/` and bodies inside `src/ops.rs` are graded.
Axes, host code, tests, crate root, and audio/vision ops are outside the permitted
overlay. Shared helpers also serve noncompetition kernels.

## Shapes and mappings

The axis definitions are authoritative; mapping `/` and `%` expressions describe
axis decomposition, rather than evaluating the axis size with ordinary remainder.
For example, `m![L % 60]` has 60 elements here, not zero elements.

| Axis | Size | Meaning |
| --- | ---: | --- |
| H | 3840 | Hidden width |
| L | 15360 | Feedforward width |
| Ns / Gs / Ds | 8 / 2 / 256 | Sliding KV heads / queries per KV head / head width |
| Qs / Ps | 4096 / 2048 | Flattened query / KV widths |
| Ts | 1024 | Sliding cache length |
| E | 32768 | RoPE table rows |
| Gf / Df / Qf / Pf / Tf | 16 / 512 / 8192 / 512 / 512 | Full-attention axes |
| W / C | 262144 / 64 | Vocabulary / auxiliary axis |
| Rv / Mv / Ov / Pv / Aa | 6912 / 3840 / 3840 / 1120 / 640 | Vision/audio axes |
| Dummy2 / Dummy8 / Dummy256 | 2 / 8 / 256 | Layout axes |

`Chip = m![1]`, `Cluster = m![1 # 2]`, `Slice = m![1 # 256]`, and
`Replicated = m![Dummy256]`. All three device entry points use
`#[device(chip = 1)]`. `EPS = 1e-6`; the model has 48 layers.

The tensor aliases have distinct type parameters:

```text
HbmTensor<Element, Chip, Elements>
DmTensor<Element, Chip, Cluster, Slice, Elements>
TrfTensor<Element, Chip, Cluster, Slice, Lane, Elements>
VrfTensor<Element, Chip, Cluster, Slice, Elements>
```

Physical mapping syntax includes axis products (comma), division, modulo,
extent constraints (`= 4`), padding/stride (`# 60`), and mutable view strides
(`#{!} 60`). Nested constraints occur in
`m![H % 120 = 4 = 2 #{!} 4, L % 1920]`. Preserve them structurally.

## Exact entry-point ABI

Every function returns `()` and starts with `ctx: &mut Context`. All other
arguments are HBM tensors. In the tables, `R` means `&HbmTensor<T, Chip, m![...]>`
and `RW` means `&mut HbmTensor<T, Chip, m![...]>`. Ordinals exclude `ctx`.
The mappings shown are the literal ABI mappings.

## Computation and physical execution

### Decoder feedforward

The complete computation is pre-RMSNorm, up/gate projections, GeGLU, down
projection, post-RMSNorm, residual addition, then layer-scalar multiplication.
Removing either the post norm or layer scalar changes the competition function.

Up/gate weights use FP4 table lookup to FP8, multiply FP8 block scales in f32,
cast to bf16, then contract with a bf16 activation TRF. Global scales are applied
after the bf16 contraction result; the kernel multiplies the supplied values.
The official fixture supplies reciprocals of `[9600, 9600, 12928]`. It does not
supply those three raw denominators.

GeGLU uses exact-erf form `up * gate * (1 + erf(gate * INVSQRT2)) / 2`,
with `INVSQRT2 = 0.70710678118f32`; scaled up and gate values are rounded to
bf16 before GeGLU. Gate stash/erf computation runs on `ctx.sub`; up multiplication
runs on `ctx.main`. Down global scaling follows the bf16 down contraction.

| Stage | Slice mapping | Elements / tuning constants |
| --- | --- | --- |
| Up/gate | L / 60 | L % 60; 60 rows/slice; 4 rows/pass; 15 passes |
| GeGLU | L / 120, 1 # 2 | L % 120; pair slices with Broadcast1(2, 1) |
| Down staging | H / 120, 1 # 8 | L; 120 output rows/slice |
| Down contraction | H / 120, L / 1920 | L % 1920; 4 rows/pass; 30 passes |
| Down dequantization | H / 120, 1 # 8 | 2 rows/half; 2 halves/pass |

Down stages each FP4 half from HBM, table-expands to FP8, applies block scales
from VRF, converts to bf16, redistributes columns through DMA, and copies two
halves into the four-row DM tile. Contraction uses outer width 32,
`contract_packet::<m![1]>`, time reduction over the row tile, and interleaved
eight-lane output. An inter-slice f32 add combines column partitions before bf16
commit. Output tiling requires mutable-stride `commit_view` mappings.

### Sliding attention output

Input `[Ns,Gs,Ds]` is reshaped to `[Qs]` and broadcast across 256 slices.
Projection splits 4096 columns into four **1024-column** contractions; each has
slice mapping `m![H / 120, 1 # 8]`. Weights table-expand FP8 to bf16. Each
partial is rounded to bf16; partials combine as `(p0+p1)+(p2+p3)` with bf16
rounding at every addition. A bf16 row scale is applied in f32 followed by a
bf16 cast. The result is redistributed to `Slice`, RMS-normalized, added to the
HBM residual, and written back. Changing split width or reduction order changes
rounding and requires correctness validation.

### Sliding QKV

Input RMSNorm precedes hidden broadcast. Q projects with slice mapping
`m![Qs / 16]` (16 rows per slice); K and V use `m![Ps / 8]` (8 rows per slice).
K/V share one activation TRF. FP8 weights table-expand to bf16, contraction
results round to bf16, channel scales multiply in f32, and outputs round to bf16.
Each projection gathers its rows with `Broadcast1 { slice1: 256, slice0: 1 }`.
Q and K then receive headwise RMSNorm with weights; V receives headwise RMSNorm
without a weight. All normalize over `Ds = 256` with `EPS = 1e-6`.

RoPE distributes heads to `m![1 # 32, Ns]` using
`InterTranspose { slice1: 8, slice0: 1, time0: 1 }`. Each 256-wide head swaps
its two 128-element halves through tiled commits. It multiplies the original by
cos and swapped values by sin, adds in f32, casts to bf16, and gathers heads
with `Broadcast1(8, 1)`. The **sin table already negates its low half**; the
kernel's swap does not negate values. Q is stored to `q_out`; K/V scatter one
cache row. The fixture uses theta 10000 and full rotary factor 1.

### Shared norms, residuals, and movement

Hidden RMSNorm redistributes to `m![1 # 32, H / 480]` with `m![H % 480]`
elements. It computes local squared sums / 3840, reduces across the eight H
partitions into `m![1 # 32, Dummy8]`, adds epsilon, takes sqrt, divides input,
multiplies the RMS weight, then broadcasts with `Broadcast1(8, 1)` and casts to
bf16. Weight and RMS operands stage into f32 VRF on `ctx.sub`.

Residual addition uses eight 480-element tiles, stages the residual in f32 VRF,
and uses `vector_clip(Add)` on `ctx.main`. The layer scalar stages to f32 VRF.
`broadcast_hidden` and `broadcast_sliding_heads` use `ctx.main`, one full-width
fetch, `CustomBroadcast { ring_size: 256 }`, 16-element collection, and trim.
These full-ring broadcasts are physical schedule choices, not model semantics.

HBM contains external weights, scales, activations, tables, and caches. DM holds
redistributed activations, weight tiles, dequantized weights, and rounded
intermediates. TRF holds contraction operands; VRF holds f32 vector operands.
`ctx.tdma` performs HBM/DM and DM/DM transfers; `ctx.sub` stages TRF/VRF and also
computes the GeGLU gate. `ctx.main` performs contractions, vectors, switches,
casts, and commits. The scheduler decides lifetimes and overlap; source types
alone do not establish peak allocation or cycle counts. Main and sub share
Tensor Unit resources; TRF halves are assigned automatically by the scheduler.

## Operation inventory

The inspected ops/helpers use the following actual DSL methods:

```text
view view_mut reshape tile transpose switch
to_dm to_dm_view to_hbm_view dma_gather_scaled dma_scatter
begin fetch fetch_cast fetch_table_lookup collect
cast commit commit_trim commit_view to_trf to_vrf
contract_outer contract_packet contract_time contract_lane
vector_init vector_final vector_intra_slice_tag vector_stash
vector_narrow_split vector_narrow_trim vector_widen_concat vector_widen_pad
vector_fp_binary vector_fp_div vector_fp_unary vector_clip
vector_intra_slice_reduce vector_inter_slice_reduce
```

Required vector operands include constants, VRF references, and `Stash`.
Operations include MulF on Mul0/Mul1, AddF, SubF, DivF, Erf, Sqrt, Exp, Tanh,
clip Add/Min, intra-slice Add/Max and inter-slice Add. Tanh belongs to the
logits path in `ops.rs`; Exp/Max/Min belong to sliding attention, which is
outside the three Stage 1 targets. The sliding attention helper also uses
`m![Ts / 8, 1 # 2]` for QK, `m![Ns, Ts / 32]` for AV, and
`Broadcast1(128, 2)` to gather logits. Its mask clips exponentials and its
softmax sum adds epsilon before division.

## Build, schedules, and correctness

Run from the official or generated overlay crate:

```sh
mkdir -p target/schedules
cargo furiosa-opt compile ops::decoder_feedforward --exact --dump-schedule target/schedules/decoder_feedforward.json
cargo furiosa-opt compile ops::sliding_attention_output --exact --dump-schedule target/schedules/sliding_attention_output.json
cargo furiosa-opt compile ops::sliding_project_qkv --exact --dump-schedule target/schedules/sliding_project_qkv.json
python3 scripts/generate_references.py
./scripts/rngd_test.sh
```

The dump flags are single-kernel options. `--exact` avoids substring matching.
Other flags are `--dump-visa`, `--dump-ir`, `--dump-dfg`, `--dump-graph`, and
`--dump-summary` (directory). `furiosa-schedule-viewer` serves port 9254.

Arena testing builds with
`cargo furiosa-opt test --release --test test_kernels --no-run --message-format=json`,
then submits the binary, fixture, and remote entrypoint with `furiosa-arena`.
`--no-build` reuses the latest binary; `--no-wait` returns after submission.
Defaults: `RNGD_POLL_SECONDS=5`, `RNGD_TIMEOUT=1800`; `RNGD_JOB_NAME` overrides
the job name. Local hardware uses `./scripts/local_test.sh`, equivalent to
`TUC_PROFILE_LEVEL=info cargo furiosa-opt test --release --test test_kernels`.

The standalone test harness executes all three cases and requires every output
element finite and `abs(actual - expected) <= atol + rtol * abs(expected)`.

| Kernel | atol | rtol | Checked outputs |
| --- | ---: | ---: | --- |
| decoder_feedforward | 0.01 | 0.01 | residual |
| sliding_attention_output | 0.05 | 0.01 | residual |
| sliding_project_qkv | 0.04 | 0.01 | q and selected k/v cache rows |

The fixture contains expected values and checksums; Rust regenerates inputs
deterministically and verifies checksums. FP4 packing puts the first value in
the low nibble. `GEMMA4_FIXTURE` overrides the fixture path. Profiling accepts
`TUC_PROFILE_LEVEL=info/debug/trace`, observes `span::npu` begin/end cycles, and
reports max end minus min begin. `GEMMA4_PROFILE_SETTLE_MS` defaults to 500.
Static schedule makespan and observed hardware cycles are separate metrics.

## Schedule schema evidence

`OPTIMIZATION.md` documents instruction `tpe`, `contexts`, `lifetime.begin/end`,
`util.total_util`, and `description` with source location/expression, plus tensor
`buffer_type`, `address`, `size`, and `shape`. Makespan is max instruction end.

A pre-existing JSON in the separate optimized checkout confirms a concrete
serialization with root keys `title`, `total_memory`, `page_size`,
`instructions`, `tensors`. Instructions also have string `index`, `history`,
numeric `input_tensors`/`output_tensors`, and util `base_util`/`efficiency`.
Tensor entries include string `index`, `name`, `physical_pages`, `fingerprint`,
and lifetime `block_begin`/`block_end`. Source descriptions use
`--> src/file.rs:line:column` followed by the expression; some descriptions are
empty. Observed contexts include DmaEngine, MainContext, SubContext,
VectorEngine, PeCore, Noop. Buffer types include Sram, Spm, Trf, Vrf.
Do not assume every buffer is HBM or every node has source attribution.
This schema sample is supporting context, not a newly generated schedule for
the pinned official commit.

## Tuning boundaries and local comparison

Candidate dimensions grounded in the baseline include broadcast ring size,
row/block distribution, up/gate and down tile sizes, down column partitions,
output-projection chunk size, vector staging, contraction lane shape, and
main/sub placement. A tile-size change must update all dependent mappings,
loops, trims, mutable views, and reduction groupings coherently. Keep numeric
casts, scales, and reduction order explicit so numerical changes are testable.

The separate local optimized repository was inspected read-only at commit
`a0899a5f48c6d0803f4a9f54f5b2f4812c26e911`. Its working tree had untracked
reports/scripts. It uses ring size 8, partitions MLP work across clusters,
30-row up/down slice groups, 3840-column down partitions, Q rows of 8 and KV
rows of 4 with cluster partitioning, and 256-column output partitions.
These are optimization context, **not the official baseline constants**.
No performance claim or correctness claim follows from inspecting that source.

This audit ran source and schema inspection only. Compilation, schedule
generation, and official hardware correctness must be recorded separately for
each generated candidate.
